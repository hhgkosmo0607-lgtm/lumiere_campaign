이 대시보드를 배포용으로 정리해줘. 링크를 받은 사람이 **이 프로젝트를 처음 본다는 전제**로 판단해줘. 채용 담당자가 30초만 보고 닫을 수도 있다.

작업 전에 어떻게 고칠지 먼저 요약해서 보여주고 내 확인을 받아줘.

## 1. 폴백이 조용히 발동하지 않게

지금은 Firestore 연결이 실패해도 샘플 데이터로 화면이 멀쩡하게 뜬다. 하단 각주 문구만 바뀌어서 놓치기 쉽다.

- 폴백 상태(`sample`, `error`)일 때 **화면 상단에 눈에 띄는 띠**를 띄워줘
- 색은 `--breakeven` 계열로, 기존 디자인 톤은 유지해줘
- `live` 상태에서는 아무것도 뜨지 않아야 한다
- 하단 각주의 상태 문구는 그대로 둬도 된다

## 2. 첫 화면에 이게 뭔지 한 줄

링크를 받은 사람은 맥락 없이 숫자부터 본다. 헤더 아래에 짧은 설명을 넣어줘.

- 가상 브랜드의 8주 광고 성과이고, 예산을 어디에 쓸지 판단하는 화면이라는 것
- 두 문장을 넘기지 마. 읽는 데 5초 이상 걸리면 안 읽는다
- 기존 `.masthead-meta` 와 톤을 맞춰줘

## 3. 가상 데이터 안내를 위로

지금은 맨 아래 각주에만 있어서 스크롤하지 않으면 못 본다. 실제 브랜드 데이터로 오해할 소지가 있다.

- 위 2번 설명 안에 자연스럽게 녹여줘. 별도 경고 박스를 만들지는 마
- 하단 각주의 자세한 안내는 그대로 유지

## 4. 링크 공유용 메타 태그

카톡이나 슬랙에 링크를 붙이면 지금은 밋밋하게 뜬다. `index.html` 에 Open Graph 태그를 넣어줘.

- `og:title`, `og:description`, `og:type`, `og:locale`
- 이미지는 아직 없으니 `og:image` 는 넣지 마. 없는 파일을 가리키면 더 나쁘다
- 나중에 스크린샷을 넣을 자리라는 걸 주석으로 남겨줘

## 마무리

- `preview.html` 에도 1~3번을 똑같이 반영해줘
- `npm run build` 통과 확인
- 폭 390px 화면에서 새로 넣은 띠와 설명이 깨지지 않는지 확인해줘
